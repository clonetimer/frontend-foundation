# 数据源对接：第一次使用指南

**数据源不是数据库，也不是自动生成后端。** 在 Studio 里，它是一张“前端怎样与后端 API 通信”的配置表。可以由项目多个组件共同引用，修改一次地址，就能同步应用到引用该数据源的列表与保存按钮。

## 先用演示接口试一遍（无需自建后端）

打开 `http://localhost:5173/studio` → 右侧「页面」→ **创建列表／详情／保存联动示例** → 右侧「数据源」→ **普通接口示例** → **测试 GET 列表与详情** → **将本页记录组件绑定到此数据源** → 顶部「体验」。

| 用途 | HTTP | 演示地址 | 用户执行什么操作 |
|---|---|---|---|
| 读取列表 | GET | `/api/studio-records` | 进入页面 / 搜索 / 翻页 |
| 读取一条详情 | GET | `/api/studio-records/{id}` | 点击列表中的一条记录 |
| 保存修改 | POST | `/api/studio-records` | 编辑标题/状态后点击保存 |
| 新增 | POST | `/api/studio-records` | 点击「＋新增」并输入标题 |
| 删除 | DELETE | `/api/studio-records/{id}` | 选中记录并确认删除 |

`{id}` 是主键占位符，发请求时会安全地进行 URL 编码。**GET 测试不会修改数据；点击新增/删除/保存是真实写入操作，演示后端为内存数据。**

## 替换为自己的后端

假设你的后端列表接口是：

```http
GET /api/tasks?page=1&pageSize=10&search=需求&status=ready&sortBy=title&sortOrder=asc
```

返回：

```json
{
  "data": {
    "entries": [
      {"key": "TASK-101", "subject": "需求确认", "state": "ready", "owner": {"name": "产品组"}}
    ],
    "count": 28
  }
}
```

那么在「数据源」中填写：

| 设置 | 例子 |
|---|---|
| 列表接口 | `/api/tasks` |
| 分页方式 | 服务端分页 |
| 记录数组路径 | `data.entries` |
| 记录总数路径 | `data.count` |
| 主键字段 | `id` |
| 显示字段 | `title` |
| 字段映射 | `id ← key`、`title ← subject`、`status ← state`、`owner ← owner.name` |
| 详情接口 | `/api/tasks/{id}` |
| 详情对象路径 | `data.item` （以你后端为准） |
| 保存接口 | `/api/tasks`（以你后端为准） |
| 新增接口 | `/api/tasks`（可选） |
| 删除接口 | `/api/tasks/{id}`（可选） |

字段映射中“保存字段名”可以填写 `subject`、`state` 等，使前端字段 `title/status` POST 时转换为后端认识的字段。

若后端列表直接返回 `[{...}]`，数组路径可留空；若有嵌套，按 `data.entries` 填写。建议先点击「测试 GET」确认能读到，再绑定本页组件。

## 为什么填了接口还连不上？

1. **404**：检查 URL / 路由和前后端是否同源。`/api/tasks` 指向当前网页部署域名下的 `/api/tasks`，不是电脑里任意后端。
2. **CORS**：浏览器直接访问不同域名/端口时，后端必须允许跨域；推荐在开发环境配置 Vite 代理，部署时通过同源网关反向代理。
3. **401/403**：需要后端用户认证和授权，Studio 不提供密钥储存；不要在设计文件、URL 里填写账号密码或 Token。
4. **空列表或取值失败**：检查返回内容中的 `data.items`/`data.entries` 路径，以及主键和字段映射。
5. **保存 422**：服务器返回字段错误，设计器会尽量映射并在字段旁提示。服务端校验仍是必要条件。

真实业务建议先在开发测试环境验证；**不要让“体验”模式直连会修改生产数据的真实接口**。API 只能在浏览器当前权限范围内使用，不能替代后端的权限校验、审计、CSRF 防护与事务处理。
