# P3 — Studio Modal/Drawer 表单安全与可访问性

基线 main \`64da52d9753ce618f7ae44169ade7dec2e85cb62\`。范围为 \`WidgetPreview.tsx\` 与按仓库既有脚本镜像的 \`exported-widgets.ts\`，确保生产编辑器与导出的独立 React ZIP 使用**完全一致的组件代码**。不修改 Foundation 0.21.0 核心契约，不改变 POST/PATCH API。

## 缺陷与处理

1. **不确定写入允许同窗重复提交**：HTTP 5xx 或超时/传输错误可出现在服务端已经完成写入之后；原组件显示“结果不确定”但 \`pending\` 清除后按钮仍可继续发送请求。P3 在同一弹窗会话内锁定提交，显示明确核对服务端的提示，禁用 Modal 主按钮和 Drawer 保存按钮；只有关闭后主动重新打开才能开启新会话。没有自动重试、没有本地伪造服务器状态。**重新打开也不证明服务端已核对，必须人工核对实际后端记录**。
2. **校验错误不能准确定位**：客户端或 400/422 服务端字段级错误虽然有 \`role=alert\`，但未与输入框建立 \`aria-invalid\`/\`aria-describedby\`，也未将焦点移至首个无效字段。P3 关联字段错误并聚焦首个无效输入；更正后错误状态同步移除。
3. 导出一致性：使用 \`tooling/scripts/sync-studio-widget-export.mjs\` 所定义的字节级镜像格式同步源文件，保留 \`--check\` 门禁。**必须同时验证生产 Studio 和独立 ZIP**。

## 验收规则

- 代码与 TypeScript：仓库现有 \`pnpm check\` 与 Studio Stable 门禁。
- 浏览器：真实 Modal/Drawer 表单必填字段提示、\`aria-invalid\`、错误与输入框 ID 对应、焦点移至首个错误、修正后状态清除。
- 传输/HTTP 503：以本地隔离的合成拦截器返回结果不确定；不得产生第二次提交、不得执行失败后续写入工作流，直至用户关闭并重新打开。合成测试绝不使用真实业务地址。
- 独立 ZIP：代码镜像同步、打包构建，且其输出的字段和提交锁定逻辑与 Studio 一致。
- 人工读屏、真实后端幂等性与事务核查：NOT RUN；不得把自动化 PASS 作为正式 Stable 签收。

## 设计边界

P3 是**同一弹窗会话**的双提交保护，不实现全局服务端幂等键、重开后自动比对记录或跨设备 CAS。正式生产环境仍应由后端提供幂等键/版本前置条件；如该能力未提供，重复写入风险无法完全消除。
