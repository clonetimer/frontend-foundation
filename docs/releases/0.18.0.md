# Frontend Foundation 0.18.0

Status: Candidate — Designer Engineering Beta

## Summary

0.18 turns the 0.17 Visual Designer proof-of-concept into an engineering beta without expanding the Project Blueprint DSL. The same `foundation.project.json` remains the only authoring document and the Project Compiler remains the only source generator.

The release focuses on editing safety and parity:

- Blueprint-level undo/redo with redo-branch invalidation;
- reference-safe rename for visual node, State, Action, Data Source and Operation IDs;
- structured Action step editor for `set`, `toggle`, `increment`, `reset`, `invoke`, and `navigate`;
- structured HTTP Data Source and Operation editors, including lifecycle and result mappings;
- Desktop / Tablet / Mobile canvas width presets;
- keyboard shortcuts and non-drag parent/reorder/delete authoring paths;
- a browser-safe private `@foundation/design-model` shared package for Designer contracts and the canonical Composition Registry;
- a release gate that verifies the packed `create-app` Registry mirror remains byte-identical to the shared canonical Registry.

## Shared design-model boundary

`@foundation/designer` no longer imports internal files from `tooling/create-app`. It consumes `@foundation/design-model` for Project Blueprint authoring types and Composition Registry metadata.

`@foundation/create-app` must remain independently publishable, so its npm package still carries `composition.json`. That file is a deterministic mirror, verified by `tooling/scripts/design-model-sync.mjs`; it is not a second independently maintained registry.

## Reference-safe rename

State rename updates:

- Widget bindings;
- Action target state references;
- Action state-value references;
- Operation `$state` query/body references;
- Operation pending/error lifecycle state;
- Operation result targets.

Action rename updates Widget Event connections. Data Source rename updates Operation sources. Operation rename updates `invoke` Action steps. Visual Node rename enforces uniqueness and identifier syntax.

## Designer interaction improvements

- `Ctrl/Cmd+Z`: Undo
- `Ctrl/Cmd+Shift+Z` or `Ctrl+Y`: Redo
- `Delete` / `Backspace`: delete selected non-root node
- `Alt+ArrowUp` / `Alt+ArrowDown`: reorder selected node
- Parent Container selector: non-drag reparenting
- Desktop / Tablet / Mobile viewport presets: 1320 / 768 / 390 px authoring widths

## Compatibility

- Project Blueprint schema: unchanged from 0.17 except `foundation.version` must align to the 0.18 minor line.
- Runtime Kernel public contract: unchanged.
- Runtime Kernel owned baseline: the reviewed 0.15–0.17 62-file baseline remains authoritative; 0.18 Designer work does not modify owned Kernel source.
- Existing 0.17 Blueprints require only normal minor-line Foundation/tooling alignment; no schema migration is introduced by Designer engineering features.
