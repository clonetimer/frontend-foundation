# Frontend Foundation 0.13.0 — Project Blueprint Candidate

Status: Candidate

## Summary

0.13 introduces the first project-level deterministic generation contract. `foundation.project.json` describes a project's Foundation profile/shell/delivery/contract selection, theme, navigation, composition pages and referenced Resource Blueprint inputs. The new `foundation-project` CLI validates that model, compiles a complete project in staging, then synchronizes it using explicit ownership rules.

Key additions:

- Project Blueprint v1 schema and semantic validator;
- `foundation-project validate|compile|status|init`;
- deterministic staging-first Project Compiler;
- generated-owned / scaffold-once / human-owned synchronization semantics;
- project/resource input hashes and managed-file state in `foundation.project.state.json`;
- Doctor Project Blueprint drift integration;
- conservative migration planning for existing Foundation projects;
- explicit generated-owned takeover during first adoption;
- generator support for `split-pane`, explicit index routes and navigation labels;
- example Project Blueprint and Resource input.

Project Blueprint remains build-time tooling. It does not introduce a runtime JSON page renderer, universal low-code DSL or a new Resource schema.

## Compatibility

- Runtime Kernel source: **intended unchanged from the 0.12.0 owned baseline**; verify with `pnpm oss:kernel-baseline` / the equivalent Node gate.
- Runtime Kernel public contract: no 0.13 additions are required by Project Blueprint.
- Existing 0.12 projects are not required to migrate. `foundation-project init` can produce an inspectable Blueprint plan; adopting Project Blueprint explicitly advances that plan to the 0.13 Foundation line, `--write` persists it, and first compiler takeover of machine-owned files requires explicit `--force-generated`.
- Existing Resource Blueprint v1 inputs remain valid and are referenced from Project Blueprint rather than embedded into it.

See `docs/PROJECT_BLUEPRINT.md`, ADR-025 and `docs/KERNEL_COMPATIBILITY_0_13.md`.

## Validation gates

Candidate evidence is recorded in repository `VALIDATION.md`. Dependency-free tooling/governance gates must pass before delivery. Dependency-backed lint/typecheck/test/build/consumer/Storybook gates remain mandatory before Stable promotion when they cannot be executed in the current environment.
