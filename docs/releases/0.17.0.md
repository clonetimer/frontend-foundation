# Frontend Foundation 0.17.0

Status: **Visual Designer PoC Candidate**

## Summary

0.17 introduces the first browser-based Visual Designer over the existing Project Blueprint model. The Designer is a private workspace application, not a second runtime or a second design schema. It edits the same `foundation.project.json` consumed by the Project Compiler.

The PoC intentionally tests whether the 0.14–0.16 model is practical for graphical authoring before expanding the DSL further.

## Delivered scope

- New private `@foundation/designer` workspace app.
- Registry-backed Layout/Widget palette.
- Registry-owned editable property descriptors shared by the Palette/Property Inspector instead of a duplicated Designer property table.
- Canvas preview using real `@foundation/ui` primitives.
- Object Tree using stable Blueprint node IDs.
- Drag from Palette to compatible containers.
- Drag existing canvas nodes to reparent them with cycle prevention.
- Split-layout two-child capacity enforcement.
- Node reorder and delete operations.
- Property Inspector for the current v1 Layout/Widget property surface.
- Binding Inspector wired to typed page state.
- Event Inspector wired to named page actions.
- Page Model panel for state/actions/data sources/operations.
- Exact JSON source view with explicit apply.
- Browser File System Access open/save when available, with import/download fallback.
- Minimal browser-side Project Blueprint shape guard before render/apply; full semantic validation remains compiler-owned.
- Designer model diagnostics for duplicate node IDs and broken binding/action references.
- Designer model regression tests and a Designer -> Blueprint -> Project Compiler round-trip test.
- `designer` and `designer:build` workspace scripts; Designer is included in release build gating.

## Architecture boundary

The Visual Designer is an **authoring frontend** for Project Blueprint. It does not introduce a runtime JSON renderer and it does not change generated application runtime semantics.

```text
Visual Designer
      |
      v
foundation.project.json
      |
      v
Project Compiler
      |
      v
ordinary React / TypeScript
```

The Palette and Property Inspector consume the existing machine-readable Composition Registry, including Layout/Widget property descriptors, Binding signatures and Event signatures. Visual tree operations mutate Blueprint `composition`; Binding/Event inspectors mutate Blueprint `state`, `bindings`, `events`, and `actions` directly.

## Compatibility

- Runtime Kernel public contract: unchanged from 0.16.0.
- Project Blueprint schema: unchanged; 0.16 Blueprints are structurally compatible after aligning `foundation.version` and tooling to the 0.17 line.
- Designer status: PoC/Candidate. It is intentionally private and is not yet a publishable Foundation package.
- File System Access API is progressive enhancement; unsupported browsers fall back to JSON import/download.

## Known limitations

- Canvas drag/drop is desktop-oriented and has not yet received touch/mobile authoring UX.
- Page-level Action/Data/Operation editing currently uses guarded JSON cards after creation; dedicated graphical step editors are deferred.
- Node ID rename is intentionally read-only in the Inspector until reference-safe rename semantics are implemented.
- Undo/redo, multi-select, clipboard, alignment guides, viewport breakpoints, and reusable custom components are not yet implemented.
- The Designer imports the first-party Composition Registry from tooling in this PoC. Before Designer stabilization, Registry ownership should move to a browser-safe shared design-model package or generated contract.
