# Frontend Foundation 0.9.0 — Developer Productivity

Status: Candidate

## Summary

0.9.0 shortens the path from a newly created Foundation application to a useful module without expanding the Runtime Kernel.

The release adds:

- committed `foundation.config.json` project manifests;
- generated Vite module auto-discovery under `src/modules/*/routes.ts`;
- publishable `foundation-generate` CLI;
- domain-neutral `page`, `management`, and `data-workbench` module patterns;
- pure-JSON custom Profile catalogs with additive `extends` inheritance;
- Doctor validation for Profile/module/config drift;
- Upgrade synchronization of project-manifest Foundation version;
- release/consumer gates that generate modules before validating packed consumers.

OpenAPI code generation is explicitly deferred. Foundation will evaluate mature upstream generators first and only add a thin integration boundary if it improves the project goal; 0.9 does not introduce a Foundation-owned partial OpenAPI parser/code generator.

## Compatibility

- Kernel public contract: unchanged from 0.8.0.
- Kernel source compatibility: eight Kernel package `src/` trees are byte-for-byte unchanged from 0.8.0.
- Existing 0.8 applications remain valid; convention-based module discovery is used by newly generated 0.9 applications and is not a Runtime Kernel requirement.
- Pre-1.0 package policy remains: all `@foundation/*` packages used by one application stay on the same minor line.

## Migration from 0.8

No mandatory Runtime source migration is required.

For projects that want the 0.9 productivity workflow:

1. upgrade Foundation dependencies to the 0.9 minor line;
2. add/commit `foundation.config.json` (newly generated projects already contain it);
3. adopt `src/modules/index.ts` convention-based aggregation if desired;
4. expose project scripts/binaries for `foundation-doctor`, `foundation-generate`, and `foundation-upgrade`;
5. rerun Doctor strict, typecheck, tests, and production build.

`foundation-upgrade --write` updates both Foundation package ranges and `foundation.config.json.foundationVersion`; it intentionally does not rewrite application source.
