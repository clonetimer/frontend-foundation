# Frontend Foundation 0.19.0

Status: Candidate

## Summary

0.19 validates the Visual Designer against the real locked Node/pnpm dependency graph and adds project-owned UI extensibility plus shared compiler-style diagnostics without turning the Designer into a runtime dependency.

- Added optional project-level `foundation.registry.json` for namespaced custom Widgets/Blocks.
- Custom Registry metadata covers package/import identity, properties, bindable types, semantic events, defaults and `acceptsChildren` authoring containers.
- Project Compiler resolves custom components to static TSX imports, adds declared package dependencies, validates required properties/Bindings/events and includes Registry bytes in project drift state.
- Designer merges project components into the existing Palette / Property / Binding / Event model but renders safe authoring placeholders instead of executing arbitrary project component code.
- Added browser-safe live diagnostics and `foundation-project diagnose --json` with stable diagnostic categories for Blueprint, Registry, Composition, Interaction and Data/Operation failures.
- Added a real Chromium Designer smoke script for Palette/history/viewport/screenshot coverage. The current hosted container blocks browser navigation to local/file/data targets by organization policy, so this gate is recorded as environment-blocked rather than passed.
- Revalidated the workspace with the supplied Node 22.23.2, pnpm 11.7.0 and offline dependency store: real TypeScript 6, ESLint, tests, production builds, Designer build and Storybook production build pass.
- Fixed two pre-existing `@foundation/ui` strict optional-property typing defects exposed by the real dependency-backed TypeScript 6 gate.

## Compatibility

- Project Blueprint v1 remains the project-level authoring model; Custom Registry is additive and optional.
- Existing projects without `foundation.registry.json` retain their previous behavior.
- Generated applications do not depend on `@foundation/designer` or the browser-safe authoring package.
- Runtime public API snapshot remains compatible. The only owned Runtime source changes are compile-contract fixes in `packages/ui/src/composition.tsx` and `packages/ui/src/visual-composition.tsx`; the reviewed 0.19 Kernel baseline contains 62 files.
- No migration is required for existing 0.18 projects unless they opt into project-owned components.
