# Frontend Foundation 0.10.0 — Contract Productivity Candidate

Status: Candidate

## Summary

0.10 adds a replaceable, tooling-only API Contract Pipeline. Projects may opt into `--contract openapi`, generate runtime-free TypeScript types, lock source/output hashes, and verify deterministic regeneration. Runtime HTTP remains owned by `@foundation/api`; the Runtime Kernel does not learn OpenAPI or generator concepts.

The first adapter is exact-pinned `@hey-api/openapi-ts@0.99.0` with only the TypeScript plugin. It remains Candidate. Foundation enables OpenAPI 3.1 only; OpenAPI 3.0 is blocked because of a known parser correctness regression in the pinned upstream line, and OpenAPI 3.2 remains pending real-upstream semantic evaluation.

## Compatibility

- Kernel public contract: unchanged from 0.9.
- Runtime package behavior: unchanged.
- Existing projects using contract mode `none`: no migration required.
- New OpenAPI projects: require the exact Candidate codegen devDependency and commit generated output plus `foundation.contract.lock.json`.
- `foundation-upgrade` realigns contract adapter metadata only when upgrading to the current Foundation line; it does not rewrite API source code.

## New tooling

Published `@foundation/create-app` now exposes:

```text
create-foundation-app
foundation-generate
foundation-doctor
foundation-upgrade
foundation-contract
```

Generated projects add:

```text
pnpm foundation:contract
pnpm foundation:contract:verify
```
