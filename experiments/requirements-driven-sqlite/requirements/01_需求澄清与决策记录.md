# 需求驱动实验 01：本地文件 → 数据库 → 条件检索 → 导出

版本：实验契约 v0.1；状态：**实验假设/待用户确认，不是正式客户签署需求**。

## 1. 用户原始业务要求（保留原文）

> 把本地数据文件，转换为数据库文件，并且支持根据查询条件，执行检索和导出。

仅从原话能够确信：有本地文件作为输入、需要数据库文件作为输出、需要根据条件检索、需要导出。**原话不指定**文件格式、数据库类型、单文件/多文件、列类型、查询语义、导出格式、权限、部署方式和数据规模。

## 4. 业务流程与成功判据

```text
本地 CSV/TXT/TSV 选取
  → 选择编码/分隔符
  → 结构及数据逐行校验（错误则结束，不留残库）
  → 生成独立 SQLite，保存字段元数据和原始文本
  → 列表可见、重启仍可查询、可以下载 .sqlite3
  → 用户选择数据库并组合查询条件
  → 结果计数、每页 50 行、稳定排序
  → 导出与最后一次执行查询一致的全部匹配记录 CSV
```

完成导入的判据不是“弹出成功通知”，而是磁盘存在有效 SQLite 头、`records` 行数与输入一致、字段映射存在、用户可再次检索与下载。

## 5. 业务与工程分界

- FF/前端职责：文件选择、参数说明、校验结果反馈、条件构建、分页表格、导出触发、空态与错误态。
- 独立本地后端职责：解析文件、SQLite 原子保存、类型识别、参数化查询、CSV 导出、文件读写/安全边界。
- 本实验使用**纯 HTML/CSS/JS** 来检验业务理解链路，故并**不能宣称已经生成了 FF Studio 项目或验证 FF 导出功能**。
- 不接入 FF 仓库、不改变冻结内核。后续要验证现有 FF 对照流程，可以用此契约在 Studio 做等价页面并独立运行，再比较实际耗时和差异。
